# SystemMonitor.Core

Папка `SystemMonitor.Core` отвечает за основную логику мониторинга.

Этот слой описывает, какие данные есть в системе, какие сервисы должны их получать и как эти данные передаются дальше.

## Главные части слоя

### Models

Папка с моделями данных.

Модель — это простой объект, который хранит результат замера.

`CpuSnapshot` хранит снимок загрузки процессора.

`RamSnapshot` хранит снимок оперативной памяти.

`ProcessEntry` хранит информацию об одном процессе.

### Interface

Папка с интерфейсами.

Интерфейс — это контракт. Он говорит, какие методы должен иметь сервис, но не говорит, как именно сервис работает внутри.

`ICpuMetricsService` описывает сервис CPU.

`IMemoryMetricsService` описывает сервис RAM.

`IProcessMetricsService` описывает сервис процессов.

### Services

Папка с реализациями сервисов.

Сервисы реально получают данные из системы.

`CpuMetricsService` читает загрузку процессора.

`MemoryMetricsService` читает состояние оперативной памяти.

`ProcessMetricsService` получает список процессов и считает их нагрузку.

### Collectors

Папка с классом, который собирает всё вместе.

`MetricsCollector` по таймеру вызывает сервисы CPU, RAM и процессов. Потом он отдаёт новые данные тем частям приложения, которые на них подписаны.

## Как работает слой

1. Сервисы получают данные из Windows.
2. Сервисы создают модели: `CpuSnapshot`, `RamSnapshot`, `ProcessEntry`.
3. `MetricsCollector` собирает эти модели вместе.
4. Внешний слой может получить готовые данные и показать их пользователю.

## Простое объяснение

`SystemMonitor.Core` — это мозг приложения. Он не рисует интерфейс, а отвечает за данные и правила работы мониторинга.
