# За что отвечает каждый файл

Документ объясняет текущие файлы проекта простыми словами. Он нужен чтобы быстро понять структуру без чтения всего кода.

## SystemMonitor.App

`SystemMonitor.App` отвечает за интерфейс приложения. Здесь находятся окно, экраны, стили и ViewModel.

### Program.cs

Точка входа приложения. Запускает Avalonia и передаёт управление классу `App`.

### App.axaml

Главный XAML-файл приложения. Подключает общую тему, стили и ресурсы, которые доступны всем окнам и экранам.

### App.axaml.cs

Создаёт главное окно после запуска Avalonia. Здесь окну назначается `MainWindowModel`, чтобы интерфейс получил данные для отображения.

### Styles/Theme.axaml

Общий визуальный стиль приложения. Здесь задаются цвета, карточки, кнопки меню, заголовки и прогресс-бары.

### ViewModels/Base/ViewModelBase.cs

Базовый класс для всех ViewModel. Он сообщает интерфейсу, что свойство изменилось, и Avalonia должна обновить экран.

### ViewModels/MainWindowModel.cs

ViewModel главного окна. Хранит текущий открытый экран и команды для переключения между обзором, процессором и процессами.

### ViewModels/OverviewViewModel.cs

ViewModel экрана обзора. Хранит общие показатели: загрузку CPU, загрузку RAM, количество процессов и время последнего обновления.

### ViewModels/CpuDetailViewModel.cs

ViewModel экрана процессора. Хранит общую загрузку CPU и список ядер с отдельной загрузкой для каждого ядра.

### ViewModels/ProcessListViewModel.cs

ViewModel экрана процессов. Формирует список процессов для таблицы и сортирует их по загрузке CPU.

### ViewModels/Converters/PercentToColorConverter.cs

Конвертер для интерфейса. Превращает процент нагрузки в цвет: зелёный для нормальной нагрузки, жёлтый для средней, красный для высокой.

### ViewModels/Views/MainWindow.axaml

Разметка главного окна. В ней есть левое меню и область, где показывается выбранный экран.

### ViewModels/Views/MainWindow.axaml.cs

Code-behind главного окна. Нужен для инициализации XAML. Основная логика находится в `MainWindowModel`.

### ViewModels/Views/OverviewView.axaml

Разметка экрана обзора. Показывает карточки CPU, RAM и процессов.

### ViewModels/Views/OverviewView.axaml.cs

Code-behind экрана обзора. Нужен только для загрузки XAML.

### ViewModels/Views/CpuDetailView.axaml

Разметка экрана процессора. Показывает общую загрузку CPU и список ядер с прогресс-барами.

### ViewModels/Views/CpuDetailView.axaml.cs

Code-behind экрана процессора. Нужен только для загрузки XAML.

### ViewModels/Views/ProcessListView.axaml

Разметка экрана процессов. Показывает список процессов с PID, именем, CPU, RAM и статусом.

### ViewModels/Views/ProcessListView.axaml.cs

Code-behind экрана процессов. Нужен только для загрузки XAML.

## SystemMonitor.Core

`SystemMonitor.Core` отвечает за основную логику мониторинга. Здесь описаны данные, контракты сервисов и сервисы чтения метрик.

### Models/CpuSnapshot.cs

Модель одного снимка CPU. Хранит время замера, общую загрузку процессора и загрузку каждого ядра.

### Models/RamSnapshot.cs

Модель одного снимка RAM. Хранит время замера, общий объём памяти, занятую память и доступную память.

### Models/ProcessEntry.cs

Модель одного процесса. Хранит PID, имя процесса, загрузку CPU, использование RAM и статус ответа процесса.

### Interface/ICpuMetricsService.cs

Контракт сервиса CPU. Описывает, что сервис должен уметь вернуть снимок процессора и количество логических ядер.

### Interface/IMemoryMetricsService.cs

Контракт сервиса RAM. Описывает, что сервис должен уметь вернуть снимок оперативной памяти.

### Interface/IProcessMetricsService.cs

Контракт сервиса процессов. Описывает, что сервис должен уметь вернуть список процессов и поддерживать фильтр по CPU.

### Services/CpuMetricsService.cs

Сервис чтения CPU. Получает загрузку процессора через системные счётчики Windows.

### Services/MemoryMetricsService.cs

Сервис чтения RAM. Получает данные об оперативной памяти через Windows API.

### Services/ProcessMetricsService.cs

Сервис чтения процессов. Получает список процессов, считает CPU по дельте между замерами и сортирует процессы по нагрузке.

### Collectors/MetricsCollector.cs

Оркестратор сбора метрик. По таймеру вызывает сервисы CPU, RAM и процессов, а потом раздаёт новые данные подписчикам.

## SystemMonitor.Tests

`SystemMonitor.Tests` отвечает за проверку сервисов. Тесты нужны чтобы быстро понять, что базовые метрики возвращаются и имеют нормальные значения.

### Services/CpuMetricsServiceTests.cs

Тесты сервиса CPU. Проверяют количество ядер, создание CPU snapshot и корректные диапазоны значений по ядрам.

### Services/MemoryMetricsServiceTests.cs

Тесты сервиса RAM. Проверяют создание RAM snapshot, неотрицательные значения и то, что использованная память не больше общей.
